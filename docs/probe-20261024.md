## 1. 两个目标各是什么

| 你说的 | 槽位 key | kind | scope | 官方实现包 |
|---|---|---|---|---|
| 权限选择框（`完全权限`） | `conversation.input.permission` | `single` | `session` | `@deepseek-ai/dsh-client-ui-permission-presets` |
| 推理等级（`Low`/`High`） | `conversation.input.model` | `single` | `session` | `@deepseek-ai/dsh-client-ui-model-selection` |

两者都在 `conversation.composer.bar` 下，同一个 input 行。

### 权限框的枚举值（`PermissionSelect.js`）

```
read-only              → 仅可查看      PermissionIconReadOnlyRegular
workspace-write        → 工作区内修改  PermissionIconWorkspaceWriteRegular
danger-full-access     → 完全权限      PermissionIconFullAccessRegular   ← 要改红的
auto                   → 自动审查      PermissionIconAutoReviewRegular
```

常量名：`FULL_ACCESS_PRESET = "danger-full-access"`（第 231 行）

### 权限框的颜色来源

```css
._86kJGG_trigger{ color:var(--dsw-alias-label-secondary) }
._86kJGG_triggerIcon{ display:inline-flex }   /* 无 color，继承父级 */
```

主题里 `--dsw-alias-label-secondary` 明暗不同。红色有现成变量：

| 变量 | 亮色 | 暗色 |
|---|---|---|
| `--dsw-alias-state-error-primary` | `--dsw-static-red-600` `#ec1313` | `--dsw-static-red-400` `#f25a5a` |
| 暗色选择器 | — | `body[data-ds-dark-theme]` |

**结论**：红色不必自己挑色，用 `--dsw-alias-state-error-primary` 即可，
明暗主题自动跟随，且与 DSH 自带危险语义同源。

### 推理等级的数据结构（host 下发）

adapter 侧（`ofm-fork/src/catalog.js`）声明 `efforts` 为**字符串数组**：

```js
efforts: ['disabled', 'low', 'high', 'max'], effortDefault: 'high'
efforts: ['light', 'balanced', 'deep'],      effortDefault: 'balanced'
```

host 规范化后前端拿到（`dsh-llm-deepseek`）：

```js
reasoning: {
  efforts: [ { id:'off', name:'Off',  description:'…' },
             { id:'low', name:'Low',  description:'…' },
             { id:'high',name:'High', description:'…' },
             { id:'max', name:'Max',  description:'…' } ],
  defaultEffort: 'high'
}
```

**关键**：`name` 是显示名，`id` 是机器值，**数组顺序就是官方 picker 的顺序**。
滑块档位必须按这个数组走 —— 这就是你说的「自适应上游下发」。

⚠️ 档数不固定：可能 1 档（`OFF_ONLY`）、3 档（light/balanced/deep）、
4 档（off/low/high/max）、6 档（disabled…xhigh）。滑块必须按长度自适应。

⚠️ 还有个隐式档：`defaultEffort === undefined` 时官方额外渲染一个
`{ effort: undefined, label: t('effort.providerDefault') }`（即 "Default"）。
所以真实档位 = `efforts.length` 或 `efforts.length + 1`。

### 切换级别的正规 API

```js
select({ provider, model, reasoningEffort: '<effort id>' })
```

由 `conversation.input.model` 的 `inject` 面提供，不需要点 DOM。
`directory`（`ModelDirectory.store`）提供当前值：

```js
state.current          // { provider, model, reasoningEffort? }
state.retainedEffort   // 当前档显示名
state.groups[]         // 全部模型
state.status           // loading | ready | selecting | error
```

## 2. 官方组件的注入面（可直接复用）

`conversation.input.model` 注册时给的 `inject`：

```js
inject: (sessionId) => {
  const directory = models.directoryFor(sessionId)
  return {
    available,                        // subagent 会话为 false
    directory: directory.store,       // 快照 store
    load: () => directory.load(),
    select: (selection) => directory.select(selection)
  }
}
```

`conversation.input.permission` 的 `inject`：

```js
inject: (sessionId) => ({
  hooks: { permissionCatalog: catalog.store },
  select: (preset) => submit(sessionId, preset)
})
```

**这意味着**：只要我注册到同一个槽位，就能拿到完全相同的
`directory` / `select` / `permissionCatalog` —— 数据与写操作都是正规通道。

## 3. 能不能「覆盖」官方组件？—— 能，但语义是 shadow

`dsh-client-ui-slots` 的 `SlotCore.register`（lib/index.js:170）：

```js
case "single": {
  const occupant = rec.entries.find(e => (e.options.priority ?? 0) === priority)
  if (occupant) throw new Error(`single slot "${name}" already has a registration
    at priority ${priority} — register at a different priority to shadow it (lowest renders)`)
}
```

- **同 priority 重复注册 → 直接抛错**（不会静默覆盖）
- **不同 priority → 共存，priority 最小者渲染**（`entriesOfSlot` 取每 cell 首个）

所以：`priority: -1` 可以遮蔽官方 `priority: 0` 的组件。

### 代价

shadow = **整个组件由我重写**。`ModelSelect` 官方实现 79KB，
包含：模型分组渲染、搜索框、键盘导航（方向键/Escape/Shift+Tab）、
`MenuSurface` 浮层定位、失败提示、toast、`routable` 校验、subagent 禁用态。

权限框小得多（37KB），但仍含确认弹窗 `RiskConfirmation`、busy 锁、
`/permission` 命令联动、settings 行。

## 4. 三条可行路线

### 方案 A：DOM 增强（CSS + MutationObserver）

不改槽位，插件在 DOM 层给现有按钮打标记/注入样式。

| 项 | 评价 |
|---|---|
| 权限变红 | ✅ 极简。一条 CSS 规则 + `MutationObserver` 监听属性变化 |
| 推理等级变滑块 | ⚠️ 要把官方菜单里的 `menuitemradio` 列表替换成滑块，属于「抢官方菜单」，官方一改结构就碎 |
| 依赖 | 官方 **hash 类名**（`_86kJGG_`）或 `aria-label` 文案 |
| 风险 | hash 类名跨版本必变；`aria-label` 随 i18n 变 |

结论：**权限变红适合 A**；滑块不适合。

### 方案 B：shadow `conversation.input.model`（推荐给滑块）

`priority: -1` 注册自己的组件，用 `inject` 拿到的 `directory` + `select`
直接渲染「模型名 + 滑块」。

| 项 | 评价 |
|---|---|
| 自适应上游 | ✅ 直接读 `reasoning.efforts`，长度任意 |
| 动画 | ✅ 完全自由（CSS transition / spring 都行） |
| 切换 | ✅ 走 `select()` 正规通道，不点 DOM |
| 代价 | 模型选择 UI 要自己写（或简化为「只显示当前模型名 + 点开复用官方菜单」） |
| 风险 | 官方升级时我这份是平行实现，需跟版本 |

**折中方案 B'**：滑块 + 模型名，模型切换点开一个**我自己写的极简列表**
（只要分组 + 选中态，不做搜索/键盘导航）。风险与工作量都小。

### 方案 C：list 槽新增独立滑块

挂 `conversation.input.dock`（`list`，`session`），官方 model 菜单不动，
在旁边多加一个滑块控件。

| 项 | 评价 |
|---|---|
| 风险 | ✅ 最低。新增 list id，不碰任何 official cell |
| 缺点 | 会出现**两个入口**（官方列表 + 我的滑块），你原话是「直接改成滑块」 |

## 5. 我的建议

| 需求 | 方案 | 理由 |
|---|---|---|
| 完全权限改红（字 + 盾牌，明暗都是红） | **A（CSS）** | 一行规则，`--dsw-alias-state-error-primary` 自带明暗。零结构风险 |
| 推理等级改滑块 + 自适应 + 预留动画 | **B'** | 只有 shadow 才能「改掉原来那个」，且 `select()`/`efforts` 都是正规面 |
| 想最稳、可接受两个入口 | C | 完全不碰官方 cell |

第一项与第二项可以**合进一个插件**：一个 `client.js`，
一半是 CSS（管红色），一半是 `priority:-1` 的 model 槽组件（管滑块）。
